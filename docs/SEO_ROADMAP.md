## 1. 方針

「何でも屋」として広く浅く狙うのではなく、**工事ごとに専門のページを持つ総合住宅設備会社**として評価されることを目指します。

```
サービスページ（Pillar）
   ├─ 下のページ（情報がそろった工事だけ。例：/service/reform/kitchen）
   ├─ 施工事例（当社が実際に行った工事の記録）
   ├─ コラム（1記事＝1つの疑問。答えたあと、サービスページへ送る）
   └─ 地域ページ（その地域にしか当てはまらない内容）
```

決まりは3つです。

1. **1つの検索意図は、1つの URL だけが担当する。** 同じ検索語を2つのページで取り合わない。
2. **確認できた事実だけを書く。** 金額・件数・資格・保証・メーカーの認定・施工地域は、資料で確かめたものだけ。
3. **ページは、中身がそろってから作る。** 地域名や工事名だけを差し替えたページは作らない。

優先順位は、①サービスページを仕上げる → ②施工事例を増やす → ③その事例に関係するコラム → ④戸塚区の地域情報 → ⑤周辺の区、の順です。
コラムの本数だけを先に増やしません。「施工した会社だから書けること」を先に書きます。

## 5. コラムの計画

### 進め方

- 1日1本。**新しい記事を書く日**と、**公開済みの記事を見直す日**があります（見直しは、理由のある記事があるときだけ。およそ3割の日）。
- 新しい記事は、`lib/blog-generator/topics.ts` の題材から、優先度（P0 → P1 → P2）の順に選びます。同じ優先度の中では、記事の少ないカテゴリが先です。
- 機械の検査（数値・決まり文句・リンク・重複・検索語の取り合い）と、読み直しの両方に通った日だけ公開します。
- 題材の主キーワードが、固定ページや公開済みの記事と同じなら、その題材は書きません（同じ検索意図の記事を2本作らない）。

### 候補を題材に上げる

`lib/blog-generator/backlog.ts` に、サービスごとの検索意図の候補があります（クラスターごとの本数は、監査の結果の表にあります）。
候補のうち `needs` が空のものは、書く内容を決めれば題材にできます。`needs` があるものは、そこに書いた確認が済んでから上げます。
数値や制度が要る候補は、先に `docs/VERIFIED_FACTS.md` に出典つきで足します。

### これから書くコラムの順番

自動投稿が選ぶ順番です（`npm run seo:audit` が書き直します）。見直しの日が入るので、日付は固定しません。
いまの題材は65件です。見直す理由のある記事が無いあいだは毎日新しい記事を書くので、およそ2か月分にあたります
（見直しの日が3割入ると、約3か月分）。足りなくなる前に、候補から題材へ上げてください。

- 隠した文字、検索語の詰め込み、同じ言葉ばかりの内部リンク
- 確認できない口コミ・施工事例・資格・料金・スタッフ・メーカーの認定
- 生成した画像を、施工事例として載せること
